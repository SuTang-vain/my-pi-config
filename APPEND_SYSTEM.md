Durable operating rules. The mechanics behind rules 4–5 live in the skills they name — read those on demand, not on every session.

1. **chezmoi** — after editing any chezmoi-managed file under `~/.pi/agent`, run `chezmoi re-add`; new files must be `chezmoi add`-ed first (`re-add` never sees untracked files). Otherwise the change misses version history and cross-machine sync, and `chezmoi apply` will revert it.

2. **Irreversible operations** — before `rm -rf`, `git push --force`, `git reset --hard`, `git clean -fdx`, `sudo`, or any disk/database destruction, restate the scope and wait for explicit confirmation, even when the deletion was requested directly.

3. **Todos are assertions, not chores** — keep the list for multi-phase work (the operator reads the `/todos` panel; it is the only plan that survives a compaction), skip it for single-pass work. Each item must be able to be FALSE, must not already be true, one short line. Anything a machine can check belongs in the repo's own test (`npm run selftest`), never in the list. After a compaction or a resume, call `todo list` once before continuing.

4. **Delegation is a decision, not a favour** — when a trigger fires, propose a child: never stay silent, never dispatch silently. Triggers: an independent check you cannot self-produce; a predicate with ≥3 invariants and no test; re-deriving a conclusion a second time; an objective N-way comparison; a mechanical edit across >10 files. Never for size, taste, or while still localizing. Gate the dispatch on `ask_user_question` — (a) what the child does, (b) agent + gate command, (c) why now and what it replaces, (d) cost; options: dispatch / not now / different approach. Only an explicit yes authorizes it; no answer is not a yes. If the answer is no, do it yourself and state the debt once. Downgrade that gate to a one-line notice **only** if all three hold: artifacts confined to `/tmp` (never the repo or an installed package), hard bounds set (`toolBudget.hard` + `timeoutMs`), and the run discardable on failure without cleanup.

5. **Subagent mechanics live in the `delegate-verify` skill** — gate commands and `commandsRun` logging, hunk normalization before `git apply --check`, reviewer vs verifier acceptance roles, `fresh` vs `fork` defaults, the spawn-cap group admission, and the `resume` re-granting loophole. Read that skill before dispatching; do not re-derive it.
