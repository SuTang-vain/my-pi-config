# my-pi-config

A public, production-used configuration for [Pi](https://github.com/earendil-works/pi), with
specialized subagents, curated skills, local extensions, and executable configuration checks.

The repository is independent of chezmoi. It installs into `~/.pi/agent`, keeps credentials and
machine state out of source control, and provides one command for updates and verification.

## Included

- Seven role-specialized agents: scout, researcher, inspector, evidence-auditor, verifier,
  reviewer, and worker.
- Local extensions for productivity, prompt snippets, context display, Markdown collaboration,
  and herdr integration.
- Curated resident skills plus an optional scientific skill library.
- npm-managed Pi extensions with machine-local host dependency links.
- A selftest harness for configuration, package resolution, skills, and extension behavior.

## Requirements

- A working Pi host (`@earendil-works/pi-coding-agent`) on `PATH`
- Node.js and npm
- `rsync`
- Git, when rebuilding the optional skill clones

Both managed Pi installations and global npm installations are supported.

## Install

```bash
git clone https://github.com/SuTang-vain/my-pi-config.git
cd my-pi-config
./install.sh --with-skills
```

The installer:

- Copies the configuration into `~/.pi/agent` (override with `PI_AGENT_DIR`).
- Backs up existing top-level settings and prompt files.
- Creates `npm/host-link` and `npm/host-deps/*` for the active Pi host.
- Installs npm dependencies and the `pi-config-update` command.
- Rebuilds the optional skill clones when `--with-skills` is present.

It does not install global npm packages, touch sessions, or overwrite an existing
`models-store.json`. Use `./install.sh --dry-run` to inspect every operation first.

Create `~/.pi/agent/auth.json` with your own provider credentials and restrict its permissions:

```bash
chmod 600 ~/.pi/agent/auth.json
```

Verify the installation:

```bash
cd ~/.pi/agent/npm
npm run selftest
```

Without provider credentials, model-reference checks are skipped with a warning. The skill
whitelist requires either `./install.sh --with-skills` or a later run of
`scripts/clone-skill-repos.sh`.

## Update

```bash
pi-config-update           # Update Pi and all extensions, repair links, run selftest
pi-config-update --dry-run # Preview without changing files
pi-config-update --host-only
```

`npm run update` from `~/.pi/agent/npm` is equivalent to the full command.

A full update runs `pi update --all`, re-resolves the active host, repairs all local host links,
installs dependencies, and runs the selftest. `--host-only` skips Pi and extension updates and
only reconciles the local host layout.

The command never runs Git operations or chezmoi.

## Version model

Shared files contain only portable declarations:

- Extension names and semver ranges in `npm/package.json`
- Unversioned npm package sources in `settings.json`
- `file:host-link` for the Pi host
- `file:host-deps/*` for direct `@earendil-works/pi-*` dependencies

Host versions are not copied into shared manifests. Each machine resolves its own active host and
creates local links to it. `npm/package-lock.json`, `node_modules/`, and the managed Pi release
directory remain local.

A host upgrade therefore changes links, not the shared manifest. Documentation version stamps,
where present, are historical audit provenance rather than update targets.

## Repository layout

| Path | Purpose |
|---|---|
| `settings.json` | Models, skills, packages, compaction, and UI settings |
| `AGENTS.md` | Verified global facts and operating boundaries |
| `APPEND_SYSTEM.md` | Durable operating rules |
| `agents/` | Specialized subagent definitions |
| `extensions/` | Local extensions and subagent configuration |
| `skills/` | Resident skills |
| `scripts/` | Installation support, updater, selftest, and session tools |
| `npm/` | Extension and host dependency declarations |
| `themes/` | Pi themes |
| `docs/` | Configuration facts, guides, and upstream issue reports |
| `models-store.example.json` | Credential-free provider and model metadata |

## Local-only content

The following never belong in the public repository:

- `auth.json`, provider keys, and other credentials
- `models-store.json`, sessions, mission data, and run history
- `node_modules/`, `package-lock.json`, and generated caches
- `npm/host-link` and `npm/host-deps/`
- Machine-specific hostnames, home paths, SSH configuration, and systemd units

`herdr-agent-state.ts` is generated by `herdr integration install pi` rather than maintained as a
portable source file.

## Development and verification

Run the updater tests and existing extension tests from the repository root:

```bash
node --test \
  scripts/pi-config-update.test.mjs \
  extensions/productivity/usage-policy.test.mjs \
  extensions/productivity/usage-inject.test.mjs
```

The selftest covers JSON validity, authenticated model references, skill discovery, native host
resolution, local host links, subagent configuration, extension entry points, and unit tests.
Failures return a non-zero exit status; warnings identify non-blocking observations.

For troubleshooting details, read `docs/pi-config-facts.md` and the other focused documents under
`docs/`. Historical design notes and measurements remain available in Git history rather than in
this operational README.
